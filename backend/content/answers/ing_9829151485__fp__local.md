**Encoding** is a *lossless* transformation that maps data into another representation while preserving every bit.  
In machine learning we use encoders (e.g., one‑hot, word‑embeddings) to convert raw symbols into vectors so that a model can process them. The mapping is deterministic and invertible: decoding yields the original input exactly.

**Encryption** solves *confidentiality*: it obscures data from anyone who does not possess a secret key.  
From an information‑theoretic view, encryption is a bijection that maximizes entropy of ciphertext under the constraint that only the key holder can invert it. Classic schemes (AES, RSA) achieve this by mixing input bits with key material so that any statistical structure in the plaintext is destroyed. In ML pipelines we encrypt data at rest or during transfer to meet regulatory requirements.

**Tokenization** lies between encoding and encryption. Tokens are opaque placeholders that reference the original value but carry no useful information on their own. They are generated by a deterministic, secret‑key–protected hash or random identifier. The key insight: tokenization preserves *uniqueness* (so that duplicate values map to identical tokens) while guaranteeing that an attacker cannot infer anything about the underlying data without the decryption key.

### Non‑obvious insight  
Tokenization is not “hashing + encryption”; it is a *controlled one‑to‑one mapping*. Because the mapping must be reversible for legitimate use (e.g., to join tables), tokenization uses a secret key and often an incremental counter or cryptographic pseudorandom function. This subtle requirement forces tokenizers to balance privacy, performance, and referential integrity—something that plain encoding or encryption alone cannot satisfy.
