**Agentic Retrieval‑Augmented Generation (RAG)**  
At its core, RAG tackles the *knowledge horizon* of language models: a static neural network can only draw on what it was trained on, yet real‑world queries demand up‑to‑date facts or domain‑specific jargon.  Agentic RAG turns the retrieval step into an *action* in a decision process rather than a passive lookup.

1. **Problem formulation** – The model must answer \(q\) while constrained by two resources:  
   *A* (the internal knowledge base, fixed) and  
   *B* (an external corpus that can be queried).  
   Each query is an *action* \(a_t\in \mathcal{A}\) (e.g., “search for X”, “filter by date”), yielding a retrieval result \(r_t\).  The goal is to maximize expected utility over the sequence of actions, akin to a Markov Decision Process with reward given by answer quality.

2. **Why it must work this way** –  
   *Optimization*: Each action has cost (latency, token budget) and benefit (information gain). A greedy policy that fetches everything is infeasible; a learned policy balances them.  
   *Information theory*: Retrieval reduces entropy about the target answer; agentic RAG explicitly estimates expected reduction per query.  
   *Geometry*: The retrieved documents are embedded in the same vector space as the language model, enabling smooth interpolation of external facts into generation.

3. **Non‑obvious insight** – Retrieval is not a lookup but a *planning* problem: the best document to fetch now may be suboptimal if it blocks a more informative query later.  Agentic RAG learns this long‑term trade‑off by treating retrieval as part of its policy network, rather than a fixed pre‑processing step.

In short, agentic RAG is an adaptive, policy‑driven bridge that lets a language model *choose* what external information to incorporate, optimizing answer fidelity under practical constraints.
