**Why we need a special storage layer**

A crawler’s job is *complete* coverage of the reachable web while respecting politeness and resource limits.  
Coverage means that every fetched URL must be remembered so it can’t be revisited and so its outgoing links can be discovered.  
Politeness demands that the same host isn’t hit more than a set rate, which requires grouping URLs by hostname.  
Resource limits (bandwidth, disk) require *prioritisation*: high‑value pages are fetched first; low‑value ones are queued or discarded.

**From these constraints to an architecture**

1. **URL frontier → priority queue + Bloom filter**  
   *Frontier* is a *heap* keyed by page importance (e.g., PageRank estimate). A *Bloom filter* guarantees that we never re‑insert the same URL, keeping memory linear in distinct URLs rather than quadratic.

2. **Host buckets → sharded hash table**  
   Each host’s queued URLs live in its own bucket. Sharding by hostname allows a single crawler thread to service one bucket at a time, enforcing per‑host rate limits without global locks.

3. **Deduplication of content → MinHash + LSH**  
   Two different URLs can point to the same document (mirrors). We compute a MinHash signature for each fetched body and place it into an *LSH* table; if a new URL maps to an existing bucket, we drop the duplicate.

4. **Persistence & fault‑tolerance → append‑only log + write‑ahead buffer**  
   The frontier is stored as an immutable log on SSD so crashes recover by replaying the tail. A small in‑memory buffer batches writes for throughput.

**Non‑obvious insight**

The *frontier* must be treated as a **stream of streams**: each host’s queue is a stream, and the global frontier is the merge of these streams. By maintaining per‑host priority queues and merging them lazily (only when a thread needs work), we avoid costly global heap operations while still honouring politeness and importance. This streaming view turns what looks like a monolithic data structure into composable, lock‑free components that scale linearly with the number of hosts.
