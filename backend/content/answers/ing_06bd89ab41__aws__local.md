**Action (Design)**  
1. **Tokenization** – Mobile devices store a *device account number* (DAN) instead of real card data; this is generated by Apple/Google on the device and encrypted with a public key held only by their payment processors.  
2. **Transaction Initiation** – The app sends an *encrypted payload* to the merchant’s backend via HTTPS.  
3. **Verification & Authorization** – In AWS, I’d route this through API Gateway → Lambda (or ECS) that calls Amazon Pay or a third‑party gateway (Stripe/Adyen).  
4. **Token Exchange** – The gateway returns a *payment token* (a short‑lived, single‑use reference).  
5. **Settlement** – The merchant forwards the token to its acquirer; settlement is handled by the payment network.

- **API Gateway** for secure, throttled entry points.
