**Idempotency in payments – the “one‑time button” trick**

Think of a vending machine that dispenses soda when you press the green button. If you accidentally hit the button twice, you might get two sodas and lose money. Idempotency is like having a built‑in safety: no matter how many times you press the button, only one soda comes out.

In payment systems, *idempotency* means giving each transaction a unique “order ID.” When the bank sees that same ID again, it knows the first request was already processed and refuses to charge the customer twice. The system keeps a tiny log of every ID it has handled; if an identical ID appears later, it simply returns the previous result instead of repeating the action.

So idempotency is just a clever way to make “double‑click” impossible—ensuring that one press (or request) equals one purchase, no matter how many times you try.
