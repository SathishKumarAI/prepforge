### Why a *Tier‑1* “Working‑Memory” layer is indispensable

The core problem any AI must solve is **real‑time inference**: given an input stream \(x_t\) and a task specification, produce an output \(y_t\) while keeping track of past context. The only way to do this without recomputing everything from scratch is to maintain a *compact, mutable* representation of the recent past—a working memory.

#### 1. Information‑theoretic motivation  
Let \(H(x_t|x_{t-1},\dots)\) be the entropy of the current input conditioned on all history. By **Data‑Processing Inequality**, any deterministic memory \(M_t\) that feeds into a predictor can only reduce this conditional entropy if it captures *relevant* dependencies. Thus, the working‑memory architecture must preserve the minimal sufficient statistics needed for the task, not raw data.

#### 2. Geometry of updates  
We view each memory state \(m_t \in \mathbb{R}^d\) as a point on a manifold. The update rule
\[ m_{t+1}=f(m_t,x_t;\theta) \]
must be a **contractive mapping** (spectral radius < 1) to guarantee stability, yet expressive enough to encode long‑range patterns. This balances the *exploration* of new information against the *exploitation* of stored context.

#### 3. Probabilistic dynamics  
A common formulation is an **RNN** with hidden state \(h_t\). Interpreting \(h_t\) as a posterior over latent variables \(z_t\), we obtain a **sequential Bayesian filter**:
\[ p(z_{t+1}|x_{\le t}) \propto \int p(z_{t+1}|z_t)p(x_t|z_t)\,dz_t. \]
Thus the working memory implements amortized inference, trading exactness for speed.

#### 4. Non‑obvious insight  
Most architectures focus on *how* to update \(m_t\), but **forgetting mechanisms are equally critical**. A learned *gate* that can erase irrelevant dimensions (e.g., via a sigmoid mask) prevents the memory from saturating with noise, effectively performing an implicit **information bottleneck**: only features that reduce downstream loss survive.
