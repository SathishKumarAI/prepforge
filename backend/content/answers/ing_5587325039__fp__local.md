**Why a Pub‑Sub Server is the Core of Real‑Time Presence**

The *fundamental problem* is to let many clients know instantly whether another client (or device) is online, offline, or in a specific state.  
We must satisfy three constraints:

1. **Low latency:** Clients learn status changes within milliseconds.  
2. **Scalability:** Thousands of concurrent connections and millions of events per second.  
3. **Consistency:** A user’s status must be reflected everywhere with minimal divergence.

A *publish‑subscribe* (pub‑sub) architecture satisfies all three by decoupling producers from consumers:

- **Publishers** emit status events (`user#123: online`).  
- **Subscribers** receive only the topics they care about (`/users/123/status`, `/rooms/42/members`).

The *deep principle* is that status propagation is a *broadcast* problem on a dynamic graph. Pub‑sub turns broadcast into a set of point‑to‑point streams, each governed by simple fan‑out logic (e.g., fan‑out to all websocket connections). This reduces the combinatorial explosion from O(n²) to O(k·n), where k is the average number of subscriptions per client.

**Non‑obvious insight:**  
Treat *subscriptions as stateful edges* rather than transient messages. Persist each edge in a lightweight key–value store so that if a subscriber reconnects, it can immediately “catch up” by replaying missed events from a *log*. This hybrid pub‑sub + event sourcing model guarantees eventual consistency without sacrificing real‑time performance.

**Key Components**

| Layer | Responsibility |
|-------|----------------|
| **Client SDK** | Maintains websocket, subscribes to user/room topics. |
| **Load‑Balanced Broker** | Routes messages based on topic hash; shards topics for horizontal scaling. |
| **State Store (e.g., Redis)** | Keeps current presence per user and subscription lists. |
| **Event Log (Kafka / Pulsar)** | Enables replay, audit, and offline‑client catch‑up. |

By deriving the design from the *broadcast graph* problem and leveraging pub‑sub’s decoupling, we achieve a system that is both highly responsive and horizontally scalable.
