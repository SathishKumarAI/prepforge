**Lost‑in‑the‑Middle: Context Engineering for LLMs**

The core problem is *information loss*: a transformer can attend only to the last ~ 4 k tokens, yet many tasks require reasoning over documents that are far larger. If we naïvely concatenate everything, the model’s attention heads saturate on irrelevant chunks and the signal from distant facts disappears—an entropy‑driven dilution.

To preserve relevance, we treat the task as a **bottlenecked inference** problem: we must compress the full document into a *structured memory* that still satisfies the information‑theoretic lower bound for the target answer. This leads to two design principles:

1. **Hierarchical summarisation** – first encode sentences or paragraphs into embeddings, then cluster them into concepts. The model only attends to the top‑level concepts during inference, reducing entropy while keeping the necessary mutual information.
2. **Dynamic retrieval** – when a token’s attention weight falls below a threshold, trigger a local lookup in an external knowledge graph that was built from the same document. This restores fine‑grained details without bloating the prompt.

A non‑obvious insight: *the retrieval step can be learned jointly with the transformer*. By back‑propagating through the indexer, the model learns to place high‑value facts in the memory where they are most likely to be requested—effectively turning context engineering into a self‑optimising compression scheme. This turns the “lost‑in‑the‑middle” problem from a static prompt design issue into an adaptive optimisation of information flow.
