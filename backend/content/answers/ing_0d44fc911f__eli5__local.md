Think of a **linked list** like a treasure‑hunt trail on paper: each clue (node) tells you where the next clue is, but it doesn’t keep all clues in one big stack. Each node holds two things—some data and a “pointer” that points to the next node’s address. If the pointer is null, the trail ends.

In coding contests, many **LeetCode** problems use this idea because you can add or remove treasures (nodes) anywhere without reshuffling the whole pile. Classic examples are:

- **Reverse Linked List** – walk the trail backward.
- **Merge Two Sorted Lists** – combine two treasure trails into one sorted trail.
- **Remove Nth Node From End** – skip to a specific spot from the back.

These problems let you practice moving through nodes, changing pointers, and handling edge cases (empty list, single node). It’s a gentle way to learn how data can be linked together without heavy overhead.
