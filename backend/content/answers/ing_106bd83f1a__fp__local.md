**From the problem to the solution**

A compliance audit asks *“does the model behave as intended?”*  
The fundamental question is: *How can we prove that an LLM’s outputs are generated by a well‑defined, traceable process rather than by opaque internal dynamics?*  

1. **Define the specification** – enumerate the required properties (privacy guarantees, bias thresholds, content filters).  
2. **Formalize the audit metric** – cast each property as a measurable function of the model’s state and input distribution.  
3. **Instrument the pipeline** – inject deterministic hooks that record token‑level provenance, attention weights, and any external API calls.  
4. **Build an audit log** – store the hooks in an append‑only, tamper‑evident ledger (blockchain or Merkle tree).  
5. **Validate post‑hoc** – run a statistical test on the logged data to confirm that every output satisfies the specification within confidence bounds.

The deeper principle is *information flow control*: we treat the LLM as an information channel and enforce that its observable outputs are a function of inputs plus certified internal states, not hidden variables.  

**Non‑obvious insight:**  
Auditability does **not** require freezing the model’s weights; instead, it requires freezing the *mapping* from input to output. By logging the deterministic attention path and token provenance, we can reconstruct the effective decision tree even as weights drift—turning a black box into a verifiable black‑box with post‑hoc interpretability.
