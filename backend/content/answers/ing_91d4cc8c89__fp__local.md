**Checkpoint‑and‑Resume as an Optimal Control of Computational State**

When training a deep network we solve a high–dimensional stochastic optimization problem

\[
\min_{\theta}\; \mathbb{E}_{x\sim\mathcal D}[\,L(f_\theta(x),y)\,].
\]

The trajectory \( \{\theta_t\} \) generated by SGD is *non‑reversible*: gradients depend on past mini‑batches and the random seed. If a failure occurs midway, naively restarting from scratch would discard all computational effort—an exponential waste of time in large‑scale regimes.

Checkpointing formalizes **state compression**: at selected iterations \(t_k\) we serialize the *complete* algorithmic state (model weights, optimizer moments, RNG state, epoch counter). This is a *surjective mapping* from the continuous trajectory to a discrete set that preserves all information needed to reconstruct the future path exactly. The key property is **idempotence**: re‑loading a checkpoint and resuming yields the same sequence \(\{\theta_{t}\}_{t\ge t_k}\) as if no interruption had happened.

From an optimization viewpoint, checkpoints act as *anchor points* that break the trajectory into independent subproblems. Each segment can be processed in parallel or on different hardware without violating convergence guarantees because the algorithm’s recurrence relation is deterministic once the state is restored. Thus checkpointing turns a globally coupled dynamical system into a collection of locally solvable modules.

**Non‑obvious insight:**  
Most practitioners only store model weights, assuming optimizer moments are irrelevant. In practice, omitting moment buffers (e.g., Adam’s \(m_t, v_t\)) changes the *effective learning rate* and can lead to divergence or stalled training after a resume. Therefore a true checkpoint must capture **all** algorithmic state, not just parameters, to guarantee exact reproducibility and optimal convergence speed.
