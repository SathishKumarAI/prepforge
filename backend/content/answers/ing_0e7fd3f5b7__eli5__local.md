**REST in plain language**

Imagine you’re ordering a pizza online. Each page of the site (menu, cart, order status) is a *resource*—a specific thing you can ask for or change.  
REST (Representational State Transfer) is like a set‑of simple rules that let your browser talk to the pizza shop’s computer:  

- **Uniform address** – every resource has its own URL, just like each pizza type has a unique link.  
- **Standard verbs** – you use GET to *look at* a menu item, POST to *add* it to your cart, PUT to *update* an order, DELETE to *remove* something.  
- **Statelessness** – every request carries all the info needed; the server doesn’t keep track of past orders between requests.

So REST is a clean, predictable way for web clients and servers to exchange data using ordinary HTTP actions, just as you click “add” or “checkout” on any website.
