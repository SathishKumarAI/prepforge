Think of a microservice like a single LEGO brick that must fit perfectly into a larger model.  
**1. Keep it tiny** – one brick, one job.  
**2. Name it clearly** – label the brick so everyone knows its purpose.  
**3. Use simple APIs** – only expose the doors (endpoints) needed for other bricks to attach.  
**4. Store data locally** – each brick holds its own pieces; no shared storage that clutters the whole set.  
**5. Run in isolation** – let every brick run on its own power supply so a fault in one doesn’t fry another.  
**6. Auto‑scale by demand** – duplicate bricks only when traffic spikes, like adding extra blocks to support weight.  
**7. Test each piece alone** – unit‑test the brick before attaching it to the model.  
**8. Monitor with lights** – watch health metrics; a red light on one brick warns you instantly.  
**9. Version and update independently** – upgrade a single brick without re‑building the whole set.

These rules let you build, swap, or fix parts of your system without breaking everything—just as a LEGO model stays sturdy even if you replace a single block.
