### Value‑Paged Attention in vLLM

The core problem is that a transformer’s self‑attention requires storing *key* (K) and *value* (V) tensors for every token. For long contexts, the V tensor dominates memory—each value vector is twice as large as its key counterpart in many models. vLLM tackles this by **paging out** only the V tensors while keeping K in fast GPU memory.

1. **Why paging works**  
   The attention score \( \alpha_{ij} = \frac{Q_iK_j^\top}{\sqrt{d_k}} \) depends solely on Q and K. Once scores are computed, the soft‑max weights can be applied to V:  
   \[
   O_i = \sum_j \alpha_{ij}V_j .
   \]
   Thus we never need all V tensors simultaneously; we only need them when their corresponding scores are used. This is a classic *cache‑coherence* problem: the keys form a read‑only “index”, while values are the mutable data.

2. **Implementation**  
   vLLM keeps K in GPU memory and streams V from CPU (or NVMe) on demand, using an LRU policy aligned with token order. When a new token arrives, its V is fetched; when it slides out of the attention window, its page can be evicted.

3. **Optimization principle**  
   The technique leverages *temporal locality*: each value is used only for a short span of queries before it becomes irrelevant. By treating V as pageable data, we reduce GPU memory by ~50 % while incurring negligible bandwidth overhead thanks to burst‑aligned fetches.

4. **Non‑obvious insight**  
   Many think that paging V will break the soft‑max because weights are pre‑computed. The key realization is that *soft‑max can be applied after each partial sum*—the algorithm accumulates weighted values incrementally, keeping intermediate sums in GPU registers. Thus, even with out‑of‑order value fetches, numerical stability is preserved.

In short, value‑paged attention solves the memory bottleneck by exploiting the separable structure of attention: K stays resident, V is streamed on demand, and incremental accumulation guarantees correct results.
