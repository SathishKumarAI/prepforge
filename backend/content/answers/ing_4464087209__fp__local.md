**What is a Language Processing Unit (LPU)?**  
At its core an LPU is a hardware accelerator engineered for the *attention*‑driven computations that dominate modern language models. The fundamental problem it solves is **dense, highly parallel matrix–vector operations with irregular data access patterns**—the dot products inside self‑attention and feed‑forward layers.  

An LPU maps each attention head to a lightweight compute tile:  
1. **Tile‑level parallelism:** Each tile owns its own scalar ALUs, small on‑chip SRAM for key/value pairs, and a dedicated bus to the global memory. This reduces latency by keeping data local.  
2. **Streaming dataflow:** Tokens stream in as a pipeline; the LPU performs *broadcast* of queries across keys and accumulates weighted sums without intermediate shuffling.  
3. **Low‑precision arithmetic:** Mixed‑precision (e.g., 8‑bit integer for weights, 16‑bit float for activations) keeps throughput high while preserving model accuracy.  

The design is a direct application of *information bottleneck* theory: by keeping the most relevant bits (attention scores) on‑chip and discarding raw embeddings early, the LPU minimizes memory traffic—an optimization that would be impossible on general‑purpose CPUs.

**Non‑obvious insight:**  
Most people focus on FLOPs, but the real performance gain comes from *reducing data movement*. LPUs achieve this by co‑locating computation and storage at the tile level, turning what is usually a memory‑bound problem into a compute‑bound one—essential for ultra‑fast inference in edge or cloud settings.
