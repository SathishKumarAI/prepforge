Think of a library.  
In **REST** you ask for one book at a time: “Give me the author of *1984*.” The server sends that single book back and you have to make another request if you want the title or reviews. Each request is a separate door.

With **GraphQL**, there’s only **one door**—the single endpoint (often `/graphql`). Inside, you hand the server a “menu” of what you need: “Give me the author, title, and reviews for *1984*.” The server reads that menu, fetches everything in one go, and returns exactly what you asked for. No extra doors, no over‑fetching or under‑fetching.

So GraphQL’s single point of entry is like a universal library desk: ask once, get all the requested data together. REST uses many specialized desks, each handling a specific type of request.
