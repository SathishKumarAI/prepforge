Imagine a café that serves coffee one cup at a time. If every customer tried to grab a cup all at once, the barista would be overwhelmed and the line would freeze. Rate limiting is like setting a rule: “Only three people can order per minute.” It keeps traffic smooth, prevents crashes, and ensures everyone gets service in turn.

In machine learning systems—whether training models or answering user queries—the same idea applies. A model or API can only handle so many requests at once before it slows down or fails. Rate limiting caps the number of calls (e.g., 100 per second) so that the server stays responsive and stable, just like the café rule keeps the barista from drowning in orders.
