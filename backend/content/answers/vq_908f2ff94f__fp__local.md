### Creating a Stand‑by Database (Oracle)

**Problem it solves**  
A standby database is a *logically consistent* copy of the production database that can take over instantly if the primary fails. It guarantees **zero data loss** for transactions committed on the primary, while keeping the primary free for write operations.

**Why it works this way**  
1. **Archiving on the primary** – every redo generated by the primary is written to an *archive log* (physical) or streamed as a *logical redo stream*.  
2. **Transport service** – these logs are transferred over the network to the standby.  
3. **Recovery on the standby** – the standby applies the received logs in order, replaying every committed transaction. The recovery engine treats the standby exactly like a normal database, so it stays in sync.

The deeper principle is *causal consistency* from distributed systems: all operations that are causally related must appear in the same order on every replica. Redo logs enforce this ordering without needing to lock the primary or serialize transactions.

**Non‑obvious insight**  
A standby can be **active** (open for read) while still receiving and applying redo. The key is *separate‑scoped* recovery: the standby’s own transactions are isolated from the incoming stream by using a dedicated *recovery thread*. Thus you get read‑scale on the standby without sacrificing fail‑over speed.

#### Step‑by‑step

1. **Prepare the primary**  
   ```sql
   ALTER DATABASE ARCHIVELOG;
   ALTER SYSTEM SET LOG_ARCHIVE_DEST_2='SERVICE=standby';
   ```
2. **Create a backup of the primary** (RMAN or full file copy).  
3. **Restore the backup on the standby host**, set `db_unique_name` to a different value, and create a `spfile`.  
4. **Configure recovery parameters** (`LOG_ARCHIVE_DEST_1`, `LOG_ARCHIVE_DEST_2`, `DB_FILE_NAME_CONVERT`, etc.).  
5. **Start the transport service** on the primary:  
   ```sql
   ALTER SYSTEM SET LOG_ARCHIVE_CONFIG='DG_CONFIG=(primary,standby)';
   ALTER SYSTEM SWITCH LOGFILE;
   ```
6. **Start the recovery thread** on the standby:
   ```bash
   sqlplus / as sysdba <<EOF
   STARTUP NOMOUNT;
   RECOVER MANAGED STANDBY DATABASE USING CURRENT LOGFILE DISCONNECT FROM SESSION;
   EXIT;
   EOF
   ```

Once the first archive log is applied, the standby becomes *ready* and can be switched to read‑only or promoted at any time.
