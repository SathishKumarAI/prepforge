## Why a “car‑already” dataset forces a different ML pipeline

When you start with an **already‑driven** vehicle—say a fleet that has logged millions of miles—you are not solving *how to learn from scratch* but *how to refine a model that already knows the world*.  
The fundamental problem is **distribution shift**: the new data come from a slightly different distribution than the training set (new weather, new road geometry, updated sensors).  

### 1. The core principle
From an information‑theoretic viewpoint, you want to minimize the *Kullback–Leibler divergence* between the true driving distribution \(P_{\text{real}}\) and your model’s predictive distribution \(Q_\theta\).  
If \(P_{\text{real}}\) has changed, the gradient of the loss will point in a direction that pulls \(Q_\theta\) toward the new data. But if you treat the new data as *labels* for a supervised learner, you risk **overfitting to noise** (e.g., transient sensor glitches).  

### 2. Why fine‑tuning works
Fine‑tuning a pre‑trained network is essentially solving:
\[
\min_{\Delta \theta}\; D_{\text{KL}}\!\big(P_{\text{real}}\,||\,Q_{\theta+\Delta \theta}\big)
\]
with a **small learning rate**. The small step size guarantees that the updated parameters remain close to the prior model, preserving learned invariances (e.g., edge detectors in early layers).  
This is analogous to *regularized* maximum likelihood: you penalise large deviations from the baseline.

### 3. One non‑obvious insight
Most practitioners treat fine‑tuning as “just a smaller learning rate”. The deeper truth is that **the *effective* number of trainable parameters shrinks** because the early layers’ gradients are heavily dampened by weight decay and low LR.  
Consequently, the model behaves like a **feature extractor** that adapts only its decision head to the new distribution—exactly what you want when the car’s sensors stay the same but road conditions change.

### 4. Practical Python tip
```python
# Freeze early layers
for param in base_model.parameters():
    param.requires_grad = False

# Only train top classifier
optimizer = torch.optim.Adam(classifier.parameters(), lr=1e-5)
```
This keeps the bulk of the learned representation intact while allowing the network to adapt quickly.

In short, when a car is “already” driving, you are not *building* from scratch but *shifting* your belief distribution; fine‑tuning with a tiny step size is the principled way to do it.
