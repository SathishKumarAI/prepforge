Think of a startup’s app as a restaurant that needs to serve customers, but the owner doesn’t want to hire cooks or buy ovens.  
With **serverless computing** on Amazon Web Services (AWS), the restaurant can call a “cook‑as‑a‑service” whenever it gets an order. AWS brings a virtual kitchen (the server) only for that one meal, then shuts it down when finished. The startup pays only for the cooking time, not for idle ovens or overnight staff.

Key terms:  
* **Serverless** – you don’t manage physical servers; the cloud provider does.  
* **AWS Lambda** – the “cook” that runs code on demand.  
* **Event‑driven** – the cook starts when something happens (a new order, a file upload).  

For startups, this means lower upfront costs, automatic scaling as orders spike, and no need to worry about keeping servers running 24/7. The result is a lean operation that grows with demand instead of paying for unused capacity.
