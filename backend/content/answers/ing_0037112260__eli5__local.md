Imagine a busy café that serves coffee (the “server”) to customers (the “clients”). In a tiny shop, one barista can hand out all the cups – that’s a single‑server model. As more people come in, the barista gets overwhelmed and orders pile up. To keep everyone happy, the café hires more baristas or opens a second counter—this is **scaling**.

In computing, the server runs the machine‑learning model (the coffee recipe). Clients send data requests (orders) to it. When traffic grows, we can scale in two ways:

1. **Horizontal scaling** – add more servers, like new baristas, each running the same ML model so they share the load.
2. **Vertical scaling** – give a single server a bigger machine—more RAM or GPUs—so it can handle more requests at once.

Just as the café keeps customers satisfied by adding staff or upgrading equipment, a client‑server architecture expands resources to serve many users without slowing down.
