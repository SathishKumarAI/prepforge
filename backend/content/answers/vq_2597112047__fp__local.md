**When does “enough” become “valid”?**

Start with the *problem* that data engineering solves: estimating a quantity (mean revenue, click‑through rate, error rate) from a finite sample so that the estimate is useful for decision‑making.  
Mathematically we want  

\[
P\!\left(\bigl|\hat{\theta}-\theta\bigr| \leq E\right)\ge 1-\alpha ,
\]

where \(E\) is an acceptable error margin and \(\alpha\) the risk of a wrong conclusion.  
Assuming independent, identically‑distributed observations with variance \(\sigma^{2}\), the central limit theorem gives

\[
\hat{\theta}\sim N\!\left(\theta,\frac{\sigma^{2}}{n}\right),
\]

so  

\[
P\!\left(\bigl|\hat{\theta}-\theta\bigr| \leq E\right)
= 1-2\Phi\!\Big(-\,\frac{E\sqrt{n}}{\sigma}\Big)\ge 1-\alpha .
\]

Solving for \(n\) yields  

\[
n \;\ge\; \left(\frac{z_{\alpha/2}\,\sigma}{E}\right)^{2},
\]

the classic *sample‑size formula*.  
Thus **enough data** is the smallest \(n\) that satisfies this inequality.

### Deeper principle

This result is an instance of *variance reduction* in estimation: every extra record shrinks the standard error by \(\sqrt{1/n}\). It also reflects the bias–variance trade‑off—more data lowers variance but may reveal hidden biases (e.g., non‑stationary streams).

### Non‑obvious insight

The formula assumes independence and a fixed \(\sigma\). In streaming or time‑series pipelines, **effective sample size** can be far smaller because autocorrelation inflates the true variance. A naïve “more data = better” strategy fails unless you account for correlation structure—often by estimating an *autocovariance* matrix or using block‑bootstrap techniques.

So, in practice: compute the target \(E\) and \(\alpha\), estimate \(\sigma^{2}\) from a pilot sample, adjust for autocorrelation if necessary, and then apply the formula. That is how many records you truly need to claim a valid outcome.
