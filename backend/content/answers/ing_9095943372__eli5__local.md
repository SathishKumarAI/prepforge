Think of Instagram as a huge library where every photo is a book page that people can read, annotate, or recommend to friends.

**Likes** are like sticky notes: anyone can slap one on a page, but the note disappears when they leave the room (the app). The system keeps a simple counter for each page and a set of user‑IDs who have left a note, so we can show “123 likes” and know who liked it.

**Comments** are like handwritten margin notes. Each comment is stored with its author, timestamp, and content. To display them quickly, the library keeps an index that maps a book page to all its comments, sorted by time or popularity.

**Shares** are like lending the page to another reader. When a user shares, we create a new “copy” record pointing back to the original photo and note who shared it. The copy is stored in the recipient’s feed so they see it as part of their own library.

All three use simple data structures (hash maps for counters, lists for comments, foreign keys for shares) but are replicated across many servers so that millions of users can interact instantly without slowing down the whole library.
