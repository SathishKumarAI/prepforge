**Prompt engineering is the art of steering an autoregressive language model by crafting its input context so that the output distribution aligns with a desired objective.**

1. **Fundamental problem** – A transformer learns to predict the next token given all previous tokens, optimizing cross‑entropy on massive corpora. Its internal representation is a *conditional probability* \(P(t_i \mid t_{<i}, \theta)\). To use it as a tool rather than a black box, we must shape this conditional distribution.

2. **Why it must work this way** – The model’s parameters are fixed; the only controllable variable is the conditioning sequence. By adding *prompts*—synthetic tokens that encode task instructions, examples, or desired style—we bias the hidden states toward a sub‑space of the language manifold where the target distribution has higher mass.

3. **Deeper principle** – This is a form of *information bottleneck*: we compress the task specification into a short context while preserving maximal mutual information with the output we care about. Prompting leverages the model’s learned inductive biases (syntax, world knowledge) as a prior over latent task variables.

4. **Non‑obvious insight** – The *order* of prompt elements matters because self‑attention weights decay with distance. Placing critical instructions closer to the token position being predicted yields stronger gradients during inference, effectively turning the prompt into a “soft anchor” that the model’s attention must respect.

In short, prompt engineering reframes the language model as an implicit Bayesian inference engine whose inputs act as priors steering its generative distribution toward user goals.
