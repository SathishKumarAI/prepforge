**Why a “type” matters in an RDBMS**

A relational database is a mathematical abstraction: a set of tables (relations) linked by keys. The *type* of database is the cost–benefit trade‑off you impose on that abstraction—how much flexibility, speed, consistency, and durability you allow.  
From an optimization perspective each type chooses a different point in the “query latency vs. write throughput” spectrum while satisfying ACID or BASE constraints.

| Type | Core design choice | When to use |
|------|-------------------|-------------|
| **OLTP (Transactional)** | Strict row‑level locking, minimal indexing overhead | High‑frequency, short transactions (e‑commerce checkout). |
| **OLAP (Analytical)** | Pre‑aggregated cubes, columnar storage | Complex ad‑hoc queries on historical data. |
| **NewSQL** | SQL interface + distributed in‑memory execution | Cloud services needing horizontal scaling without abandoning ACID. |
| **NoSQL‑like RDBMS** | Schema‑on‑write with optional JSON columns | Semi‑structured logs or events where schema evolves. |
| **In‑Memory** | Entire dataset resides in RAM, flash fallback | Real‑time analytics (e.g., fraud detection). |
| **Embedded** | File‑based storage, minimal external dependencies | Mobile apps, IoT edge devices. |
| **Cloud‑native** | Serverless compute + elastic scaling | Workloads with bursty traffic and variable cost constraints. |
| **Graph‑enhanced** | Edge tables for adjacency lists | Social networks or recommendation engines. |
| **Temporal** | Validity timestamps stored per row | Auditing, versioned data pipelines. |
| **Spatial** | R‑tree indexes on geometry columns | GIS, location services. |
| **Geospatial‑partitioned** | Sharding by latitude/longitude | Global map services. |
| **High‑availability cluster** | Multi-master replication with conflict resolution | Mission‑critical banking systems. |
| **Immutable ledger** | Append‑only logs + hash chaining | Blockchain‑style audit trails. |
| **Hybrid transactional–analytical processing (HTAP)** | Single engine for both OLTP and OLAP workloads | Real‑time dashboards on live data. |

*Non‑obvious insight*: The “type” is not a new technology but a *policy* about where to place consistency guarantees in the query execution graph. Choosing the right type means deciding **which part of the system will pay for latency**—the lock manager, the storage engine, or the network fabric—rather than simply picking a vendor or feature set.
