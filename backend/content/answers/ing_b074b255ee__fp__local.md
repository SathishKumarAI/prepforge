**Why we need clock sync in a TSP**

A time‑series processor (TSP) samples data at regular intervals defined by an internal clock. If two TSPs run independently their clocks drift relative to each other because of oscillator tolerances and temperature changes. When the processors later merge or compare streams, even microsecond misalignments corrupt correlation, event timing, and downstream inference.

**Fundamental principle: deterministic sampling → deterministic alignment**

The TSP’s state machine is a finite‑state automaton that must transition at precise moments to keep the sample buffer in sync with the analog front end. The only way to guarantee this across multiple units is to anchor each clock to a common physical event—an *aligned counter*.

**Hardware aligned counters**

An aligned counter is a shared, high‑frequency ring oscillator (or PLL output) that emits a clean pulse once per system cycle. Each TSP taps this pulse into its own local counter and uses it as a reference tick. Because the pulses are generated by the same source, their phase relationship is fixed; any drift is eliminated.

**Non‑obvious insight**

The key benefit is not just eliminating drift but *reducing jitter* in the local clock. By counting aligned pulses rather than relying on an internal oscillator, each TSP inherits the low‑phase‑noise properties of the shared source. This subtle advantage improves time‑domain resolution without adding complex PLLs to every chip.

**Bottom line**

Synchronizing TSP clocks with hardware‑aligned counters solves the core problem—deterministic sample alignment across devices—by anchoring local timers to a common, stable pulse train, thereby eliminating drift and jitter while keeping the design simple.
