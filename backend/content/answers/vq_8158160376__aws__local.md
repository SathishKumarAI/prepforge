**Answer – Managing Schema Drift in Azure Data Factory**

> **Leadership Principles:** *Customer Obsession* + *Ownership*  

### Situation  
In a production ETL pipeline ingesting daily CDC feeds from an on‑prem CRM, we observed that the source schema was adding new columns every month. The downstream data warehouse (Synapse) began throwing “column mismatch” errors, halting business reporting.

### Task  
I had to devise a robust, automated solution that allowed the pipeline to adapt to schema changes without manual intervention while ensuring data integrity for our analytics customers.

### Action  
1. **Enable Schema Drift** in ADF mapping data flows and set *Allow Additional Columns* to true.  
2. **Dynamic Sink Mapping:** Use a *Lookup* activity to fetch the current target table’s column list from Synapse metadata, then build an *Expression* that maps only matching columns.  
3. **Versioned Staging** – Write each run into a Snowflake‑style `raw_<table>_v<timestamp>` partition; this preserves every schema snapshot for audit and rollback.  
4. **Monitoring & Alerting:** Create a Logic App that scans the staging tables for new columns, triggers an Azure Function to update Synapse’s `INFORMATION_SCHEMA.COLUMNS`, and sends an OpsGenie alert if drift exceeds 3%.
