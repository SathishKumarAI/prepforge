**Beam Search: a principled compromise between exhaustive and greedy decoding**

The core problem in sequence generation (e.g., language modeling) is to find the most probable output \(y^*=\arg\max_y P(y|x)\).  
Exact search is exponential; a greedy decoder keeps only one hypothesis, risking early mistakes. Beam search relaxes this by maintaining *k* best partial hypotheses at each time step:

1. **Forward propagation**: for every current beam element, generate all next‑token probabilities \(P(\cdot|y_{<t})\).  
2. **Scoring**: compute the cumulative log‑probability (or a length‑normalized variant) for each extended hypothesis.  
3. **Pruning**: keep only the top *k* by score; discard the rest.

Mathematically, beam search implements a *branch‑and‑bound* strategy on the directed acyclic graph of all possible sequences, with *k* as the bound width. It guarantees that if *k* equals the total number of hypotheses (i.e., exhaustive search), we recover the optimal sequence; as *k* decreases, the algorithm trades off optimality for speed.

**Non‑obvious insight:**  
Beam search implicitly performs a *partial dynamic programming*. Each beam element stores not just the best score but also the entire partial history. Because scores are additive in log space, pruning after each step preserves all information needed to reconstruct any later extension that could beat the current best. Thus, unlike naive breadth‑first search that would recompute identical prefixes repeatedly, beam search reuses computations across beams—making it both efficient and near‑optimal without exploring the full combinatorial tree.
