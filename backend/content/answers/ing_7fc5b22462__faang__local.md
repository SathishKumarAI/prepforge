**Clarify**  
Prompt injection asks an LLM to follow malicious user instructions (e.g., reveal secrets). The core problem: *how to guarantee correct behavior when the model’s output is generated by a probabilistic neural net that can be coaxed into any text.*  
Assumptions I’d confirm: we’re dealing with off‑the‑shelf, fine‑tuned models; no ground truth about user intent; and the system must remain usable for legitimate queries.

**Approach**  
1. Treat it as a *security* issue: formal guarantees vs. statistical defenses.  
2. Identify all attack vectors (direct injection, prompt concatenation, prompt rewriting).  
3. Evaluate defense families: token‑level filtering, instruction‑level prompting, model‑side auditing, and post‑generation verification.

**Depth**  
- **Statistical defenses** (e.g., temperature control, nucleus sampling) only reduce risk; they do not eliminate it because the model can still generate any token with non‑zero probability.  
- **Token filtering** blocks obvious illicit words but fails on obfuscated or paraphrased requests.  
- **Instruction prompting** (“You are a helpful assistant…”) is heuristic and brittle—malicious users can craft counter‑instructions.  
- **Model‑side auditing** (e.g., detecting high‑confidence “secret” tokens) requires redefining the loss function and re‑training, which introduces new vulnerabilities.  
Hence, no single technique offers *provable* safety; every defense either leaks privacy or hurts utility.

**Edge Cases**  
- Ambiguous prompts where legitimate intent overlaps with malicious patterns.  
- Transfer attacks: a benign prompt that triggers a chain of internal calls revealing data.  
- Adversarial tokenization changes that bypass filters.

**Optimize & Communicate**  
Future work must formalize *prompt safety* as an objective, perhaps via adversarial training or differential privacy guarantees, and provide audit trails for every model decision. I’d explain to interviewers that the unsolved nature stems from the probabilistic, open‑ended output space of LLMs combined with evolving attack strategies—making a definitive fix inherently impossible without sacrificing core functionality.
