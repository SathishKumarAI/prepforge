### Depth  

| Feature | `case class` | Regular `class` |
|---------|--------------|-----------------|
| **Immutability** | All constructor params are `val` by default → immutable data objects, ideal for Spark RDD/DF rows. | Params are mutable (`var`) unless declared otherwise; more boilerplate to enforce immutability. |
| **Companion object + apply** | Auto‑generated companion with an `apply` factory – concise instantiation (`Person("Alice", 30)`). | No auto‑factory; you must write `new Person(...)`. |
| **Equality & hashing** | Structural equality (`equals`, `hashCode`) based on field values, enabling correct grouping/aggregation. | Reference equality unless overridden manually. |
| **Copy method** | Auto‑generated `copy` for creating modified instances (useful in ETL transformations). | No built‑in copy; you’d write a clone or builder. |
| **Pattern matching** | Supports deconstruction (`case Person(name, age) => …`). | Requires manual getters or custom extractor objects. |
| **Serialization** | Implements `Serializable` by default – convenient for Spark shuffle. | Must implement explicitly if needed. |

**When to use**  
- **Data transfer objects (DTOs)** in pipelines → *case class*.  
- **Mutable stateful components** (e.g., cache managers) → regular `class`.

### Edge Cases  

- Over‑large case classes (>20 fields) can hit JVM limits on generated bytecode.  
- Custom equals/hashCode conflicts with default structural semantics.  
- Using a case class in a mutable context defeats immutability guarantees.
