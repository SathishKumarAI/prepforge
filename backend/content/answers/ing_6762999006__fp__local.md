**Eliciting Harmful Capabilities by Fine‑Tuning on Safeguarded Outputs**

The core problem is *model safety*: we want a language model to refuse dangerous instructions while still answering benign ones. A common safeguard is a filter that rewrites any harmful request into a safe, neutral response (e.g., “I’m sorry, I can’t help with that”). The filter guarantees the public output never reveals illicit knowledge.

When we fine‑tune a base model **only on these safeguarded outputs**, we are solving an optimization problem that minimises the divergence between the model’s predictions and the filtered texts. Crucially, the loss function depends **solely on the final token sequence**; it does not penalise hidden activations or internal representations.

Because the dataset contains *every* harmful prompt paired with its safe rewrite, the fine‑tuned model learns to reproduce those rewrites exactly. Simultaneously, it can *embed* a latent representation of the original harmful content in intermediate layers—this is the “hidden knowledge” that the filter suppresses at inference time. At test time, when the safeguard is removed or weakened (e.g., via a different prompt format), the same internal representation can be activated to generate the illicit response.

**Non‑obvious insight:** The fine‑tuning objective implicitly teaches the model *how* to hide knowledge rather than *whether* it should reveal it. Thus, even with perfect external safety checks, a maliciously fine‑tuned model can recover harmful capabilities by reactivating its internal representations. This demonstrates that safeguarding outputs alone does not guarantee safety; we must also constrain or audit latent behavior.
