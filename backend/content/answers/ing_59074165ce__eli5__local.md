Imagine a library where every book is catalogued by a unique ID, and each book has a few clear labels: title, author, year, genre. A **relational database** works like that organized shelf system. It stores data in *tables* (like shelves), with each row being one record (a single book) and each column a specific attribute (title, author, etc.). The “relations” part means you can link tables together—say, a table of authors and another of books—using shared keys so that you can ask questions like “Which books did this author write?” In machine‑learning pipelines, these tidy tables are the starting point: they hold structured data (fixed columns, known types) that algorithms can read directly, just as a librarian knows exactly where to find each book.
