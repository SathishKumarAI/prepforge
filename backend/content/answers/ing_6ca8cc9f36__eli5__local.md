Imagine a community garden where everyone plants seeds (code) and shares the harvest (results). In machine‑learning projects on GitHub, the “seeds” are the scripts that train models, and the “harvest” is the accuracy or new features people can use.

**GitHub** is just a big online notebook for these seeds.  
**Repository (repo)** is one garden plot—a folder with all the files.  
**Fork** means you copy the plot to your own space so you can grow it without touching the original.  
**Pull request (PR)** is like showing your neighbors a new plant and asking, “Can we add this to the shared garden?” If they approve, your changes join the main plot.

To contribute:  

1. Fork the repo.  
2. Create a new branch in your fork for the feature you’ll work on.  
3. Write or improve code (e.g., add a new preprocessing step).  
4. Commit your changes with a clear message.  
5. Open a PR from your branch to the original repo’s main branch.  

The project maintainers review, discuss any tweaks, and merge if it fits. That’s how you help grow machine‑learning knowledge together.
