### Indexing in Search Engines – A First‑Principles View

At its core, a search engine solves **the inverse retrieval problem**: given a user query \(q\), find all documents \(d\) whose content best matches \(q\). Naïvely scanning every document would cost \(\mathcal{O}(N)\) per query—impossible for billions of pages. The solution is to pre‑compute an **inverted index** that trades storage for speed.

1. **Tokenization & Normalization**  
   Each document \(d\) is broken into tokens (words, n‑grams). We normalize (lowercase, stem, remove stop‑words) so semantically identical terms map to the same key. This reduces dimensionality and aligns with the *bag‑of‑words* assumption: order is ignored because relevance depends on term occurrence, not sequence.

2. **Posting Lists**  
   For each token \(t\), we store a posting list \(\mathcal{P}_t = \{(d_i, f_{i,t})\}\) where \(f_{i,t}\) is the frequency of \(t\) in document \(d_i\). This structure embodies *sparsity*: most tokens appear in few documents, so lists are short. The index thus implements a sparse matrix representation of the term‑document incidence.

3. **Query Decomposition & Boolean Retrieval**  
   A query is decomposed into its tokens \(\{t_1,\dots,t_k\}\). Intersection (AND) or union (OR) of posting lists yields candidate documents in logarithmic time, exploiting set operations on sorted lists—an optimization rooted in *information‑theoretic* compression: we store only the “interesting” entries.

4. **Ranking via TF‑IDF / BM25**  
   Each candidate \(d\) receives a score
   \[
   \text{score}(q,d)=\sum_{t\in q}\log\!\Bigl(\frac{N}{n_t}\Bigr)\cdot \frac{f_{d,t}}{f_{d,t}+k_1(1-b+b\,|d|/avg\_dl)},
   \]
   where \(N\) is total docs, \(n_t\) documents containing \(t\). This formula derives from maximizing the likelihood that a document generated by a probabilistic language model matches the query, balancing term frequency against inverse document frequency—an *information‑theoretic* principle.

**Non‑obvious insight:**  
The inverted index is essentially a **sparse linear operator** applied to the query vector. Retrieval boils down to matrix–vector multiplication in compressed form. Recognizing this links search engines to modern machine learning (e.g., sparse embeddings), suggesting that advances in efficient linear algebra can directly speed up indexing without changing the underlying semantics.
