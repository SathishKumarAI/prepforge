**Rate‑Limiting & Resource Quotas: The Geometry of Safe AI**

At the core, an AI system is a *function* \(f:\mathcal{X}\rightarrow\mathcal{Y}\) that maps user inputs to outputs. Every call to \(f\) consumes *resources*: compute cycles, memory, network bandwidth, and—most critically—the *information budget* of the model’s internal state (weights, activations). If we let users invoke \(f\) arbitrarily, the system behaves like a black‑box with unbounded input streams. From an optimization standpoint, the objective is to minimize expected loss while keeping resource consumption below a hard ceiling; this is a constrained optimisation problem \(\min_{\theta}\mathbb{E}[L(f_\theta(x),y)]\) s.t. \(C(\theta)\leq B\).

Rate‑limiting imposes an *upper bound* on the frequency of calls, effectively shaping the feasible set in the time dimension: it guarantees that the cumulative resource usage over any window stays below a threshold. Resource quotas extend this to multidimensional constraints (CPU hours, GPU minutes, token limits), turning the feasible region into a high‑dimensional polytope.

**Why it Must Work This Way**

1. **Safety** – By bounding how often and how much data can be processed, we prevent runaway training or inference that could corrupt shared parameters or leak private information (an information‑theoretic leakage bound).
2. **Governance** – Quotas enforce policy compliance (e.g., no more than X sensitive queries per day), making the system auditable: each quota violation is a discrete event that can be logged and traced.

**Non‑obvious Insight**

The *shape* of the resource polytope matters. A naive “one token per request” rule forces a *lattice* schedule, but a *soft* linear constraint (e.g., weighted sum of CPU and GPU usage) allows the system to reallocate resources dynamically: if a GPU becomes idle, the quota can shift weight from CPU to GPU without violating overall limits. This fluidity reduces waste and improves throughput while still guaranteeing safety guarantees—an insight that often gets overlooked in static rate‑limiting designs.
