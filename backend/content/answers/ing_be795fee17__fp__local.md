**Technical Assessment Best Practices – Why They Must Work**

1. **Problem‑first design**  
   *Fundamental question*: “What real‑world task must the candidate solve?”  
   By framing assessment around a production‑style problem, we force candidates to trade off accuracy vs latency, memory vs throughput—exactly what an AI engineer does on a live system.

2. **Layered difficulty**  
   *Principle*: *Cognitive load theory*.  Start with a simple baseline (e.g., logistic regression) and layer complexity (feature engineering, distributed training).  This reveals both foundational knowledge and the ability to scale solutions.

3. **Quantifiable metrics**  
   *Optimization view*.  Provide a clear objective function (e.g., maximize F1 under 50 ms inference).  Candidates must decide how to weight constraints—mirroring real‑world engineering trade‑offs.

4. **Live coding + artifact review**  
   *Information theory*: The code is the channel; its entropy (readability, documentation) reflects maintainability.  Reviewing artifacts (pipelines, notebooks) surfaces design thinking and reproducibility.

5. **Behavioral anchoring**  
   *Probabilistic reasoning*.  Ask candidates to explain why a model failed on edge cases—this tests their understanding of distribution shift and uncertainty estimation.
