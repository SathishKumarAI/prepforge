## The Core Agent Loop: From Goal‑Directed Decision Making to Tool Use

At its heart an AI agent is a **probabilistic policy** π(a|s) that maps a *state* s (the world’s observable snapshot) to an action a, chosen so as to maximize expected future reward R.  
The loop  
1. **Observe** → sₜ  
2. **Plan / Reason** → decide aₜ = argmaxₐ π(a|sₜ)  
3. **Act** → execute aₜ (possibly invoking an external tool)  
4. **Receive feedback** → next state sₜ₊₁, reward rₜ  

is simply the iterative application of *Bellman’s principle of optimality*: an optimal policy must be optimal at every step.  

### Why Tool Use Fits Naturally
A tool is nothing more than a deterministic or stochastic function T: S×O→S (where O are optional arguments). The agent treats it as any other action:  
- **State transition** becomes sₜ₊₁ = T(sₜ, o)  
- **Reward signal** can be shaped to reflect the tool’s usefulness.  

Thus “tool use” is just an expansion of the action space with richer semantics; no extra machinery is required.

### Deeper Principle: Information Bottleneck
Choosing a tool compresses high‑dimensional sensory data into a concise, task‑relevant representation (e.g., parsing text to a JSON schema). The agent implicitly solves an *information bottleneck* problem: maximize mutual information I(T(s); goal) while minimizing the cost of accessing T. This explains why agents learn to delegate complex sub‑tasks to specialized tools rather than overfitting monolithic models.

By treating every external routine as part of the environment’s dynamics, the agent can compose arbitrary pipelines (e.g., *search → parse → summarize*) through pure reinforcement learning, without hard‑coding any symbolic rules.
