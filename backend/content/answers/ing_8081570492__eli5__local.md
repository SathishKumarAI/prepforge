Imagine a library where each book is a *SSTable*—a file that stores many rows of data sorted by key. Over time, new editions (updates) arrive; old copies pile up next to the newest ones, but only the latest copy matters for any reader. **Compaction** is like a librarian who periodically gathers all these books on a table, rewrites them into one fresh edition that contains only the most recent pages, and then discards the outdated volumes.  

In ScyllaDB, compaction runs automatically with different *strategies* (like choosing which books to combine first). A **size‑tiered** strategy mixes many small tables into a larger one; a **leveled** strategy keeps each level roughly the same size and only merges when a level is full. The goal: keep the database fast by reducing the number of files that must be scanned for every query, just as a single updated book is easier to find than dozens of old copies.
