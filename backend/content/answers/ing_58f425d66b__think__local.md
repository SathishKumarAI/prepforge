**Metacognitive Guide: Explaining a “Problem Statement – Code Assistant”**

1. **Clarify the Audience & Scope**  
   *Ask:* Who will read this? (students, developers, managers?) What level of detail is required? Assume the reader knows basic programming but not the specific problem context.

2. **Adopt a Problem‑Solving Framework**  
   Use the classic “Problem → Goal → Constraints → Example” structure: identify what needs to be solved, why it matters, what limits exist (time, resources), and illustrate with a concrete input–output pair.

3. **Step‑by‑step Reasoning**  
   - *Define the task*: e.g., “write a function that transforms X into Y.”  
   - *State assumptions*: e.g., “input is a list of integers; output must be sorted ascending.”  
   - *Break down constraints*: runtime, memory, edge cases.  
   - *Provide an example*: show sample input and the expected output to anchor understanding.

4. **Avoid Common Pitfalls**  
   - Don’t overload with jargon; keep language simple.  
   - Avoid vague terms (“efficient”)—specify measurable limits (O(n log n)).  
   - Don’t assume prior knowledge of the specific algorithm unless it’s part of the learning goal.

5. **Sanity‑Check & Communicate Clearly**  
   - Read the statement aloud: does it flow logically?  
   - Ask a peer to paraphrase; if they’re confused, adjust wording.  
   - End with a concise summary that reaffirms the objective and constraints, so readers can mentally “check” their understanding before coding.

Use this checklist each time you draft or review a problem statement for a code assistant—ensuring clarity, completeness, and usability.
