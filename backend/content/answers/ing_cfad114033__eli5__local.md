Think of building a kitchen.  

**Imperative (step‑by‑step)** is like a recipe: you tell the cook “take the pan, heat it, add oil, stir, then add onions.” The focus is on *how* to get from one state to the next.  

**Functional (stateless) programming** is like a vending machine that gives you a pizza slice each time you press a button. You give it an input (the button), and it returns a result without changing anything inside—no memory of past slices, just pure input‑output.

**Object‑oriented programming (OOP)** is the kitchen itself: rooms (objects) such as the stove, fridge, or pantry each hold their own ingredients (data) and tools (methods). You can ask a room to “cook” or “store,” and it knows how to do it using its internal state.  

So imperative = recipe steps, functional = vending machine outputs, OOP = rooms that own data and actions. Each style gives a different way to organize the same cooking task.
