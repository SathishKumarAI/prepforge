**Why you need a managed OpenSearch domain**

When an app must expose search‑heavy analytics (e.g., log inspection, product catalog, or user activity), the raw problem is *fast retrieval of high‑dimensional text/JSON data at scale*.  
A dedicated cluster solves this by:

1. **Indexing** – mapping documents to inverted‑index shards that enable sub‑second term lookups.  
2. **Scalable storage & compute** – each shard lives on an EC2 instance; adding nodes increases throughput linearly, while Elastic Search’s query planner keeps latency bounded.  
3. **Security & governance** – fine‑grained IAM policies and encryption at rest/traffic keep compliance straightforward.

Amazon OpenSearch Service abstracts the operational overhead (patching, autoscaling, snapshots) so you can focus on *data modeling* rather than cluster maintenance.

**Embedding dashboards**

1. **Create a domain**  
   ```bash
   aws opensearch create-domain \
     --domain-name my‑app-search \
     --engine-version OpenSearch_2.3 \
     --cluster-config InstanceType=r6g.large.search,InstanceCount=2 \
     --ebs-options EBSEnabled=true,VolumeSize=100,VolumeType=gp3
   ```
   The `r6g` family gives high memory‑to‑CPU ratio, ideal for query caching; `gp3` SSD ensures low I/O latency.

2. **Enable access policies**  
   Attach an IAM role that grants the application’s task role read/write rights and a resource‑based policy that allows the *OpenSearch Dashboards* endpoint to be called from your VPC or via a CloudFront distribution.

3. **Publish dashboards**  
   In OpenSearch Dashboards, create visualizations (e.g., Kibana Lens) and export them as *iframe URLs*.  
   ```html
   <iframe src="https://my‑app-search.us-east-1.es.amazonaws.com/_dashboards/app/discover?embed=true" width="100%" height="600"></iframe>
   ```
   The `embed=true` flag strips navigation, making the view behave like a widget.

**Non‑obvious insight**

Embedding dashboards does **not** mean embedding *data*.  
The iframe still performs REST calls to OpenSearch; thus the domain’s network policy (e.g., VPC endpoint or security group) must allow inbound traffic from your web tier. If you forget this, the dashboard will silently fail, leading developers to blame JavaScript errors instead of networking misconfigurations. Ensuring a secure yet open route is the key to a smooth user experience.
