### What it is

When an AI assistant (or a language‑model pipeline) changes the *prompt* that will be fed to the next inference step, **the “run‑before” hook** is code that executes immediately before that change takes effect. The same hook fires when the underlying model is swapped (e.g., from GPT‑4 to Claude). In practice it’s a tiny function or script that can log state, validate inputs, or adjust configuration.

### Why it must run

1. **Consistency**  
   Every prompt or model switch alters the *context space* the network operates in. A pre‑change hook guarantees that any side effects (caching, token limits, logging) are applied uniformly—avoiding drift between sessions.

2. **Safety & Integrity**  
   If a malicious payload is injected into a new prompt, the hook can detect and sanitize it before the model sees it, acting as a guardrail.

3. **Performance Tuning**  
   Switching models often requires re‑initializing embeddings or tokenizers. The hook can pre‑warm caches so the next inference starts with minimal latency.

### Deep principle

This pattern is an instance of *pre‑condition enforcement* in software design, analogous to *gradient clipping* in training: it ensures that each step begins from a well‑defined state. By treating prompt changes as “state transitions,” we enforce invariants (e.g., maximum token length) just as we enforce loss bounds during optimization.

### Non‑obvious insight

Most people treat prompts like raw text, ignoring the *meta‑state* of the model (tokenizer buffers, context window). The pre‑change hook is a simple but powerful way to make that meta‑state explicit and controllable—turning implicit assumptions into verifiable, testable conditions. This leads to reproducible experiments and safer deployment at scale.
