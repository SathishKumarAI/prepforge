**Schema – the “blueprint” for data**

Think of a database like a library.  
*In an **SQL** (relational) library, every book must fit into a pre‑designed shelf layout: title, author, ISBN, genre—all in fixed columns. The *schema* tells you exactly where each piece goes; if a new type of information appears (say, “publisher country”), the whole blueprint must be updated and the shelves rearranged.*

*In a **NoSQL** library, shelves are flexible. A book can have any number of tags—author, color, mood—without fitting into a rigid slot. The *schema* is optional; each record (or “document”) decides its own shape on the fly.*

So, SQL = strict, pre‑planned structure; NoSQL = adaptable, schema‑free structure. Both keep data organized, but they choose different ways to do it.
