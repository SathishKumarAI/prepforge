2. **Approximate Nearest‑Neighbour (ANN)** search is required because exact nearest‑neighbour in millions of vectors costs \(O(N)\).  ANN reduces complexity to sublinear time by partitioning the space with locality‑sensitive hashing or tree‑based structures, guaranteeing an \(\epsilon\)-recall bound.  
3. **Distributed indexing** shards the vector collection across nodes; each shard runs a lightweight ANN index (e.g., HNSW).  Query routing uses *routing keys* derived from the query embedding to hit the most relevant shards first, reducing network traffic.  
4. **Pre‑filtering and caching**: Frequently queried or high‑ranked passages are cached in fast memory; low‑value results are streamed lazily.  

The deeper principle is that retrieval is an *information bottleneck*: we compress the knowledge base into a subspace that preserves relevance while enabling efficient search.  
**Non‑obvious insight:** In practice, **query‑driven shard selection outperforms uniform sharding** because it concentrates bandwidth on the most promising vectors, dramatically lowering latency without sacrificing recall. This adaptive routing turns what would be a static ANN problem into a dynamic, query‑aware system that scales linearly with document volume while keeping response times in the tens of milliseconds.
