Think of a system‑design interview as building a LEGO model of a city.  
You’re asked to describe how you’d lay out roads, power lines, and traffic lights so the city runs smoothly. Coding is not part of that conversation—you’re not actually snapping together bricks or writing code for the cars.  

Instead, you explain the **architecture**: what parts (databases, caches, load balancers) you’d use, how they talk to each other (APIs), and why you chose them (latency, cost). You might sketch a diagram or walk through data flow, but you don’t write any code.  

If the interviewer later asks “how would you implement X?” you can outline the logic in plain terms, maybe give pseudocode, but the interview is mainly about design thinking, trade‑offs, and communication—not actual coding.
