Think of a client‑server system like ordering food from a restaurant.  
The **client** (you) sits at the table, looks at the menu, places an order, and waits for the server (the kitchen) to deliver the dish.  

What you **do not do** is cook the meal yourself – that’s the job of the server. In technical terms:  
- You send a request for data or a command.  
- The server processes it, runs calculations, accesses its database, and sends back a response.  
- You only receive and display that response.

So the thing **not done at the client** is *executing the requested operation on the server’s resources*—the heavy lifting stays with the server.
