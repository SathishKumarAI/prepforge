**Active‑Passive Policy (Availability Pattern)**  
Think of a busy highway that has two lanes: one lane is always open for traffic (the **active** lane), while the other lane is kept clear but ready to take over if something happens to the first lane (the **passive** lane). In IT, an *active* server processes all user requests. The *passive* server sits idle, mirroring the active one’s data and state. If the active server crashes or needs maintenance, the passive server instantly takes over—traffic keeps flowing without a noticeable pause. This setup guarantees high **availability** (service is almost always up) while keeping costs lower than running two fully active servers all the time. The key terms: *active* – working, handling requests; *passive* – standby, ready to step in.
