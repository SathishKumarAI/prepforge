**What’s an API? A “Translator” for Apps**

Think of a software program as a chef in a kitchen. The chef has recipes (its code) but can’t just throw ingredients into the fridge—he needs a clear way to ask for them. An **API (Application Programming Interface)** is that waiter: it tells the chef *what* to say, *how* to say it, and *where* to get the answer.

When two companies want to share data or services, they use **partner APIs**—a special menu written in a common language so each side’s “chef” can request what it needs without guessing. The API defines:
- **Endpoints** (menu items) – where to send requests.
- **Methods** (orders) – GET for asking, POST for sending new data.
- **Responses** (food delivered) – the structured answer the chef receives.

So an API is simply a standardized conversation bridge, letting apps talk to each other smoothly—just like a well‑trained waiter ensures every dish reaches the right table.
