### The hardware that turns math into models

At the heart of every machine‑learning system is a **computational engine**: a set of physical circuits that perform arithmetic, store data, and move it around with minimal latency.  
* **CPU & GPU (graphic card)** – CPUs are general‑purpose “brains” optimized for low‑latency branching; GPUs are massively parallel “hands” that execute the same instruction on thousands of data points simultaneously—exactly what a neural network needs when multiplying tensors.  
* **Motherboard** – the nervous system that routes power, clock signals, and inter‑device communication (PCIe lanes, DDR buses). Its design dictates how many GPUs can be attached and how fast they talk to each other.  
* **Memory cards / RAM / Hard/SSD drives** – short‑term memory stores active tensors; long‑term storage holds datasets and checkpoints. SSDs offer the low‑latency random access that CPUs need for pre‑processing, while HDDs are cheaper for archival data.  
* **Power supply & cooling devices** – provide stable voltage and dissipate heat generated by dense transistor arrays; overheating throttles GPU clock speeds, breaking the linear scaling assumption of stochastic gradient descent.  
* **Peripherals (desktop, monitor, pen drive)** – humans read results, edit code, and transfer models. The display’s resolution and color fidelity influence debugging visualizations, while USB drives allow rapid deployment to edge devices.

**Non‑obvious insight:** *The bottleneck in most ML pipelines is not compute power but data movement.* Even the fastest GPU cannot learn if its memory bus stalls for disk I/O or if the CPU cannot feed it mini‑batches fast enough. Thus, a balanced architecture—fast interconnects, sufficient RAM, and low‑latency storage—is as critical as raw floating‑point throughput.
