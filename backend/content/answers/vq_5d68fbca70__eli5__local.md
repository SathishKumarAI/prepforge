Imagine you’re building a Lego set. In a **statically‑typed** language, every block’s shape and color are decided before you start: the instruction manual tells you exactly which piece goes where. If you try to put a square block into a round slot, the builder (the compiler) stops you immediately—errors are caught at “build time.”  

In a **dynamically‑typed** language, the blocks are flexible. You can slide any shape into any slot, and the set will keep going until you actually try to use that mismatched piece in a way that matters (like pushing a door with a round block). Errors surface only when the program runs (“runtime”).  

So:  
- **Statically typed** = types checked before execution; errors caught early.  
- **Dynamically typed** = types checked as code runs; more flexibility, but potential runtime surprises.
