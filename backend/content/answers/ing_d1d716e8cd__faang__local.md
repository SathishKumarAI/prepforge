**Clarify**  
The problem is to build a *reward model* (RM) that scores text generated by an LLM so it can be used for reinforcement learning. I’ll assume we already have a set of candidate completions and we want to learn from human preferences.

**Approach**  
1. **Collect preference data**: show pairs of completions to humans, ask which is better (or “no preference”).  
2. **Encode each completion** using the same backbone as the policy (e.g., transformer embeddings).  
3. **Train a binary classifier** that predicts the probability a sample is preferred over its counterpart.  
4. **Use Bradley‑Terry loss** to convert pairwise comparisons into a probabilistic model.  

**Depth**  
For completions \(x\) and \(y\), let the RM output scores \(s_x, s_y\). The Bradley‑Terry probability that \(x\) beats \(y\) is  
\[
P(x \succ y)=\frac{e^{s_x}}{e^{s_x}+e^{s_y}}\; .
\]  
The loss for a labeled preference pair is  
\[
L = -\bigl[\,w \log P(x\succ y)+(1-w)\log(1-P(x\succ y))\,\bigr],
\]
where \(w=1\) if humans chose \(x\), \(0\) otherwise. This loss is differentiable and aligns the RM’s ranking with human judgments. Complexity per batch is linear in sequence length; training converges in a few epochs due to the simplicity of the objective.

**Edge Cases**  
* Tied preferences (no clear winner) → drop or weight equally.  
* Very long sequences cause saturation in exponentials → apply temperature scaling.  
* Sparse data for certain prompts → use data augmentation or hierarchical RMs.
