### Why the “Anthropic” technical interview is structured this way

**Problem:**  
Hiring a machine‑learning engineer is an optimization over two competing objectives: *skill* and *culture fit*. The interview must therefore **measure knowledge** (to solve hard problems) while **revealing reasoning patterns** that predict future performance.

1. **Screening → Fundamentals → System Design → Coding → Behavioral**  
   - **Fundamentals** test raw competence; the questions are chosen because they expose gaps in understanding core concepts (e.g., gradient descent, over‑parameterization).  
   - **System design** evaluates *abstraction* and *trade‑off thinking*: can you decompose a real‑world ML pipeline into modules, balance latency vs accuracy, and anticipate edge cases?  
   - **Coding** checks implementation speed and correctness—essential for rapid prototyping in production.  
   - **Behavioral** confirms alignment with Anthropic’s values (responsibility, safety).

2. **Why this order?**  
   The sequence mirrors the *learning curve*: start with low‑stakes, high‑yield questions to warm up; then progressively increase cognitive load while still giving candidates a chance to recover.

3. **Non‑obvious insight:**  
   **“Red herring” questions are intentional.** For example, asking about the “optimal batch size for training GPT‑4” forces you to think about *resource constraints* and *gradient noise*, not just memorized facts. Candidates who answer these correctly demonstrate a *probabilistic mindset*—they can quantify uncertainty and trade‑offs, which is crucial for safe AI.
