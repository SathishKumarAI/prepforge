**Tools vs. Sub‑Agents in Agent Design**

The core problem an autonomous system faces is *how to map a stream of observations into actions that maximize long‑term reward*. Two architectural choices address this: **tools**—hand‑crafted modules with fixed semantics, and **sub‑agents**—self‑contained decision makers trained on the same objective as the whole.

*Why tools work*: they impose a *bias* that reduces the search space. A language‑model tool for “summarize” only ever emits short text; the planner need not learn summarization from scratch, so it can focus on higher‑level planning. The underlying principle is **modularity + compositionality**: by composing simple, well‑defined behaviors we obtain a complex policy without re‑optimizing everything.

*Why sub‑agents fail when over‑engineered*: each learns its own value function; if their objectives are misaligned or redundant, gradients conflict and the system collapses into “meta‑learning” an entire pipeline. The deeper insight is that *shared representation is key*. When a tool’s output space is fixed, the planner’s policy can be represented as a simple lookup or conditional logic, dramatically reducing variance.

**Takeaway**: Use tools to encode domain knowledge and constrain outputs; reserve sub‑agents for truly novel sub‑tasks that cannot be expressed with a static interface. This balances expressiveness with learnability, avoiding the “curse of over‑engineering” where every component becomes another learning problem.
