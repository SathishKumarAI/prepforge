### Constrained Decoding vs. JSON Mode: A First‑Principles View

Both techniques aim to **guarantee syntactic validity** of a model’s output, but they differ in *where* that guarantee is enforced.

| Aspect | JSON Mode | Schema‑Constrained Decoding |
|--------|-----------|-----------------------------|
| **Guarantee location** | Post‑generation validation (parser + schema checker) | During token generation (token probabilities are pruned to stay within a valid parse tree). |
| **Granularity of control** | Only the final text is checked; any intermediate invalidity can be repaired by post‑processing. | Each step respects the grammar, so the model never leaves the set of valid parses. |
| **Overhead** | Low (just a single pass through a JSON parser). | High (the decoder must maintain a stack of possible tokens derived from the schema’s automaton). |

#### How Schema‑Constrained Decoding Enforces the Schema

1. **Model the schema as an automaton**  
   Convert the JSON schema into a deterministic finite automaton (DFA) that accepts exactly the language of all valid documents. States encode partial objects, expected keys, and value types.

2. **Prune logits at every step**  
   For each token position, intersect the model’s softmax distribution with the DFA’s outgoing transitions from the current state. Tokens that would lead to an invalid state are zeroed out before sampling.

3. **Backtrack on dead‑ends**  
   If no transition is possible (e.g., a required key is missing), the decoder backtracks or triggers a “fallback” token such as a placeholder, ensuring the run never terminates in a rejecting state.

4. **Guarantee of validity**  
   Because every accepted path in the DFA corresponds to a JSON document that satisfies the schema, any sequence generated by this constrained decoder is valid by construction—no need for post‑processing checks.

#### Non‑Obvious Insight

The *true* power of constrained decoding lies not just in preventing errors but in **biasing the model’s search space** toward semantically meaningful solutions. By pruning impossible branches early, the model can allocate probability mass to rare yet valid constructions (e.g., deeply nested objects) that would otherwise be drowned out by generic language priors. This subtle shift often yields outputs that are both syntactically correct and **semantically richer**, a benefit invisible when relying solely on post‑generation validation.
