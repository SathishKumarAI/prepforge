**Situation** – In my last role at a retail analytics firm we had an Azure Data Factory (ADF) pipeline that ran nightly to ingest and transform 200 GB of transactional data. The release cycle was manual: developers pushed changes to the “dev” ADF instance, then an Ops engineer exported JSON, manually deployed it to prod, and rolled back if something broke. This caused a 3‑day window for each deployment and a 2% error rate on production runs.

**Task** – I was tasked with automating the entire flow: from code commit to automatic validation in dev, to promotion into test and prod, ensuring rollback capability and auditability, all within an Azure DevOps pipeline.

**Action** – I set up a GitHub repository for ADF artifacts and enabled “Git integration” on ADF. Using ARM templates generated by the “Export to ARM” feature, I stored each pipeline, dataset, linked service as JSON in Git. In Azure DevOps I created a YAML pipeline that:
1. **Checks out** the repo.
2. Uses `az deployment sub create` with the ARM template to deploy to a *dev* resource group, running an ADF self‑test via PowerShell (`Invoke-ADFRun`) to validate connectivity and data quality.
3. If successful, promotes the same artifact set to a *test* environment, then finally to *prod*, each step gated by manual approvals.
4. Stores deployment logs in Azure Monitor and sends Slack alerts on failures.

**Result** – Deployment time dropped from 3 days to under 30 minutes for every change. The automated test caught 95 % of issues before prod, reducing production errors from 2% to <0.5%. I also documented the pipeline as a reusable template that other teams adopted, saving them an estimated 20 hrs/month in manual effort.
