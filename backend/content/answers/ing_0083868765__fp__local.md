**Fertility of a tokenizer**  
A language’s *fertility* is the expected number of sub‑tokens produced per source token. Formally, for a corpus \(C\) and tokenizer \(T\),

\[
f_T = \frac{\sum_{s\in C} |T(s)|}{|C|}
\]

where \(|C|\) counts original tokens (e.g., words or characters). Fertility captures how “fine‑grained” the tokenizer is: a high value means many splits, implying higher lexical coverage but more sequence length.

**Why it matters**  
In transformer training, sequence length drives quadratic memory and compute. If two languages have the same raw token count but one has \(f_T=1.5\) and another \(f_T=3.0\), the latter will consume roughly twice as many attention operations. Thus fertility is a *direct proxy* for computational cost per language.

**Python snippet**

```python
from collections import Counter
import re

def tokenize(text, pattern=r'\w+'):
    """Simple word tokenizer; replace with your library."""
    return re.findall(pattern, text)

def fertility(corpus_file, tokenizer=tokenize):
    total_tokens = 0   # original tokens (lines)
    total_subtokens = 0
    with open(corpus_file) as f:
        for line in f:
            words = line.strip().split()
            total_tokens += len(words)
            subts = sum(len(tokenizer(w)) for w in words)
            total_subtokens += subts
    return total_subtokens / total_tokens

print(fertility('spanish.txt'))   # e.g. 1.23
```

**What to do with the result**

| Result | Action |
|--------|--------|
| **High fertility** | Consider a longer BPE merge threshold or switch to a character‑level model if memory is constrained; alternatively, cap sequence length during training. |
| **Low fertility** | You can afford more context windows or larger batch sizes for that language without hitting GPU limits. |
| **Cross‑language comparison** | Use \(f_T\) to weight loss contributions so each language contributes equally in multilingual fine‑tuning. |

*Non‑obvious insight:* Fertility is *not* merely a token‑count artifact; it correlates with the **entropy density** of the language under that tokenizer. A high‑fertility tokenizer distributes probability mass over many sub‑tokens, lowering per‑token entropy and thus increasing model uncertainty—this explains why some languages need more training steps to converge even if raw data size is equal.
