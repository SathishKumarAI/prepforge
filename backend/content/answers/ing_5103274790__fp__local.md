**Why the “Architecture – System‑Design” cheat sheet is essential**

A machine‑learning production pipeline is a *constrained optimization* problem: we must minimize latency, maximize throughput, and preserve model accuracy under limited compute, storage, and budget.  
The cheat sheet encodes this trade‑off as a **design matrix**—each row represents a sub‑system (data ingestion, feature store, training cluster, serving layer, monitoring), each column a constraint (cost, SLA, scalability). By filling the matrix we automatically discover *bottlenecks* and *latent dependencies*.  

1. **Data Ingestion → Feature Store**  
   - *Why*: Raw streams are noisy; features must be reproducible.  
   - *Principle*: *Deterministic pipelines* enforce causality: every feature is a deterministic function of raw data, ensuring reproducibility of the loss surface during training and inference.

2. **Training Cluster → Hyper‑parameter Search**  
   - *Why*: Model quality is a convex surrogate over hyper‑parameters; exhaustive search is NP‑hard.  
   - *Principle*: Bayesian optimisation treats the loss as a Gaussian process, turning the discrete search into a continuous optimization problem.

3. **Serving Layer → A/B Testing / Canary Releases**  
   - *Why*: Deployment latency must stay below 100 ms for user experience; yet new models can degrade accuracy.  
   - *Principle*: *Stratified sampling* of traffic keeps statistical power high while respecting latency budgets.

4. **Monitoring & Retraining Loop**  
   - *Why*: Data drift causes model obsolescence.  
   - *Principle*: *Change‑point detection* (e.g., Page–Hinkley) turns the monitoring problem into a sequential hypothesis test, triggering retraining only when evidence exceeds a threshold.

### Non‑obvious insight

Most interviewers overlook **feature drift as a latent variable** in the system design. Treat each feature’s distribution shift as an *additional dimension* in the constraint matrix; then the optimal architecture is not just “scale up training” but often “add a lightweight feature‑validation microservice.” This microservice can pre‑emptively flag drifts, reducing costly retraining cycles and keeping the entire ML pipeline robust.
